# Retail Risk Data Mart (МСФО 9)

Прототип витрины данных для расчета стадий обесценения (МСФО 9) по розничному кредитному портфелю.

## Описание проекта

Проект демонстрирует полный цикл разработки витрины данных для банковского риск-менеджмента:

- Генерация синтетических данных по кредитам, клиентам и платежам
- Проектирование хранилища данных по схеме "Звезда"
- Расчет просрочки (DPD) и определение стадий МСФО 9
- Анализ качества данных и миграции между стадиями
- Автоматизация процесса через Airflow

## Бизнес-логика МСФО 9

| Стадия | Условие | Описание |
|--------|---------|----------|
| **Стадия 1** | DPD ≤ 30 | Кредит работает нормально, резерв = 12-месячный ожидаемый убыток |
| **Стадия 2** | DPD 31–90 | Значительный рост кредитного риска, резерв = пожизненный ожидаемый убыток |
| **Стадия 3** | DPD > 90 | Кредит обесценен (дефолт), резерв = пожизненный ожидаемый убыток |

## Модель данных

Используется схема **"Звезда" (Star Schema)**. Центральная таблица фактов: `fact_loan_status_monthly`.

### Измерения (Dimensions)

| Таблица | Описание | Ключ |
|---------|----------|------|
| `dim_clients` | Информация о клиентах | `client_id` |
| `dim_loans` | Информация о кредитных договорах | `loan_id` |
| `dim_dates` | Календарь с флагами | `date` |

### Факты (Facts)

| Таблица | Описание | Гранулярность |
|---------|----------|---------------|
| `fact_payments` | Платежи по кредитам с расчетом задержек | 1 строка = 1 плановый платеж |
| `fact_loan_status_monthly` | Статус кредитов на конец месяца | 1 строка = 1 кредит × 1 месяц |

## Ключевые показатели

| Метрика | Описание |
|---------|----------|
| `dpd` | Days Past Due — количество дней просрочки |
| `overdue_amount` | Сумма просроченной задолженности |
| `outstanding_principal` | Остаток основного долга |
| `cum_scheduled` | Накопленная сумма платежей по графику |
| `cum_paid` | Накопленная сумма фактических оплат |
| `ifrs9_stage` | Стадия обесценения (1, 2, 3) |

## Масштабирование

Текущая реализация выполнена на Python (Pandas) для прототипирования. Для промышленной эксплуатации предполагается миграция на:

- **Apache Spark (PySpark)** — для обработки больших объемов данных
- **Apache Hive** — для хранения таблиц в Hadoop-кластере
- **Apache Airflow** — для оркестрации (уже реализован DAG)
- **PostgreSQL / Greenplum** — для хранения целевых витрин
